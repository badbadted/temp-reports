# 行程網頁標準做法

> 新行程一律照這份做。網頁放在 GitHub Pages（https://badbadted.github.io/temp-reports/），在 LINE 群組由小帥維護。

## 一、開新行程（管理員，30 秒）

在要用的 LINE 群組（小帥要先開著）打：

```
/小帥 新行程 <名稱> <標題>
```

例：`/小帥 新行程 hokkaido-2028 ❄️ 2028 北海道滑雪`

- **名稱**：小寫英文、數字、`-`，會變成網址（`hokkaido-2028.html`），開了就不改。建議「地點-年份」。
- **標題**：網頁最上面的大標，之後可以請小帥改。
- 開好會自動：建資料檔、產生網頁、加進首頁清單、推上 GitHub、綁到這個群。網頁約一分鐘後上線。
- 一個群可以綁好幾份（最多 5 份）：加綁用 `/小帥 行程 <名稱>`，看全部用 `/小帥 行程`，取消用 `/小帥 行程 取消 <名稱>`。綁了好幾份時，講到年份、日期或地點，小帥就知道是哪一份；沒線索時用剛剛在講的那份，再不然用最快出發的那份。

## 二、把行程排進去（群組任何人）

直接叫小帥，用講的就好：

| 要做的事 | 怎麼說（例） |
|---|---|
| 加一天 | 小帥 新增 1/30（六）飛東京、1/31（日）岩原滑雪場 |
| 加細項 | 小帥 D1 加 13:05 華航高雄出發，17:25 到成田 |
| 改／刪細項 | 小帥 D2 晚上改成東京巨蛋點燈、小帥 刪掉 D3 第 2 項 |
| 刪一天 | 小帥 刪掉 D5（後面的天數會往前遞補） |
| 頁首 | 小帥 頁面日期寫 1/30—2/6・8 天、說明寫 高雄 ⇄ 東京 |
| 住宿／航班／成員 | 小帥 住宿寫錦糸町 5 晚、青森屋 2 晚 |
| 連結 | 小帥 加連結 巴士時刻表 https://… |
| 某天的補充資訊 | 小帥 D3 補充資訊寫巴士時刻表 08:40、09:10 |
| 照整份行程排 | 把行程打成文字貼上，請小帥照著排（小帥目前看不懂圖片） |
| 看圖 | 小帥 給我看 D4、小帥 住宿傳圖給我 |

規則（程式擋，不靠 AI 自律）：

- 每次改都會先**列出要改的內容**，群組有人單純回「好」才會改；15 分鐘內有效。
- 改好會附上改過那幾段的**截圖**，網頁約一分鐘後更新。
- 一次最多 8 個修改、最多 9 天；資訊區最多 8 塊、每塊 12 行；連結最多 15 個、只收 https。
- 小帥上網查資料的那一輪不能提修改（例外：某天的補充資訊框，會標明「內容是網路上查到的」）。
- 寫進網頁的字一律跳脫，塞不進 HTML。

## 三、兩種版面

| | 通用版面 | 手刻版面 |
|---|---|---|
| 判斷 | 沒有 `trips/<名稱>.template.html` | 有自己的模板 |
| 頁首、住宿、連結 | 在資料檔，小帥能改 | 寫死在模板，找 TED 改 |
| 每日行程、補充資訊 | 小帥能改 | 小帥能改 |
| 例子 | snow-trip-2027 | christmas-ski-trip |

新行程一律用通用版面。要做特別的視覺（像聖誕那頁的住宿卡片）才另外手刻模板，而且之後頁首、住宿就只能手改。

## 四、手動改（TED 在電腦上）

```bash
# 1. 改資料：trips/<名稱>.json（不要直接改 <名稱>.html，小帥會發現不同步而拒絕更新）
# 2. 重新產生網頁
node tools/trip.mjs build <名稱>
# 3. 確認網頁跟資料同步、測試通過
node tools/trip.mjs check <名稱>
node tools/trip.test.mjs
# 4. 只 add 這份行程的檔案再 commit、push
git add trips/<名稱>.json <名稱>.html
```

其他指令：`outline <名稱>`（小帥看到的文字版）、`describe <名稱> <ops.json>`（試改不寫檔）、`create <名稱> <標題>`（等同群組的開新行程，但不會 commit）。

## 五、注意

- Mac 上的 clone 在 `~/apps/temp-reports`，小帥每次改之前會 pull；那份 clone 有未提交的改動時，小帥會暫停更新。
- 行程結束後可以 `/小帥 行程 取消` 解除綁定；網頁留著當紀念，不用刪。
- 網頁是公開的：不要放護照號碼、電話、訂位代號這類個資。
